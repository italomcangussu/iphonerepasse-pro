# RFM Broadcast Targeting Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Criar rascunhos de broadcast com uma audiência RFM exata, limitada à loja ativa e preservada até o envio.

**Architecture:** A leitura de vendas é paginada para que o RFM tenha o histórico completo. `lib/marketing/rfmRecipients.ts` transforma clientes RFM e vendas em uma lista deduplicada de `crm_lead_id`. `broadcastDraft.ts` grava essa lista em `recipient_filters.lead_ids`. O worker e `prepare_broadcast_recipients` reconhecem a chave como filtro fechado, o que protege tanto o caminho agendado quanto o fallback do worker.

**Tech Stack:** React 19, TypeScript, Vitest, Supabase Edge Functions (Deno), PostgreSQL migrations.

## Global Constraints

- Escopo sempre é a `store_id` do broadcast; não misturar vendas de outras lojas.
- `lead_ids` presente e vazio deve resultar em zero destinatários, nunca em fallback amplo.
- Limite explícito de 500 contatos, priorizando maior valor RFM.
- Nenhuma nova tabela, RLS policy, permissão ou segredo.
- Sem personalização `{variável}` no texto do broadcast.
